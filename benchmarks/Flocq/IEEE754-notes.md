# Bit and primitive-float contracts

The source is FLoCq commit `7aab8f55bceec0cfafc3b3bc0e77e0dbb5a70c5f`. `IEEE754/Bits.v` assumes `0 < mw`, `0 < ew`, and `mw + 1 < 2^(ew - 1)` in its section. Its `binary_float` constructors also carry validity proofs. The Lean type erases those proof fields, so the float-to-bits-to-float contract explicitly requires the frozen `validBinary` predicate. Candidate validity functions cannot choose the domain of the roundtrip obligation.

`validBinary` accepts signed zero, infinity, positive NaN payloads smaller than `2^(prec - 1)`, and canonical finite representations. A finite mantissa is positive and smaller than `2^prec`; its exponent lies between `3 - emax - prec` and `emax - prec`. Below the normal-mantissa threshold `2^(prec - 1)`, only the minimum exponent is valid. At that minimum exponent, both subnormal and normal mantissas are possible.

Bits are unsigned integers, with a positive sign-bit contribution. `splitBits` returns `(sign, exponent, mantissa)`; Coq returns the last two components in the opposite order. The concrete decoder extracts those fields and handles zero/subnormal, infinity/NaN, and normal encodings. Neither decoding nor validity is an axiom.

Lean 4.29.1 declares `Float.ofBits` and `Float.toBits` as opaque external operations and provides no inverse laws. Both native operations canonicalize NaNs in the [locked Lean runtime](https://github.com/leanprover/lean4/blob/f72c35b3f637c8c6571d353742168ab66cc22c00/src/runtime/object.cpp#L1722). A universal `toBits (ofBits b) = b` law would therefore be false. The native domain embeds upstream `BinarySingleNaN` with one quiet NaN, `.nan false (2^51)`, selected by the frozen `primitiveNanCanonical` predicate. Other valid NaN payloads remain supported by the general bits interface, but cannot roundtrip through native `Float`.

Upstream `PrimFloat.v` relies on `FloatAxioms.SF2Prim_Prim2SF` and `Prim2SF_SF2Prim`. The Lean native specifications take `FloatBitsLaws` as an explicit premise about the platform primitives. Its bit-to-float-to-bit law applies only to the canonical native domain, identified by the frozen IEEE decoder. These premises mention neither candidate conversion. No global instance or new axiom asserts them. The kernel proofs establish the conversions conditionally on those laws; they do not prove the native runtime implementation satisfies the laws. Boundary execution tests separately check runtime behavior, including NaN canonicalization. The chosen quiet NaN matches the tested Linux runtime; a different platform representation requires an explicit model update.

The curator test `tests/lean/flocq_contracts.lean` checks the general bit roundtrips, decoder validity, and conditional native roundtrips with the kernel. It lives outside the shipped benchmark so implementation-specific proof scripts do not constrain generated candidates. `Flocq.Test` checks signed boundaries, minimum normal and subnormal values, infinities, NaN payloads, and every encoding of a small valid format. The benchmark keeps all scored obligations. Specification and reference changes invalidate previous scores; re-render and re-evaluate artifacts against this revision.
